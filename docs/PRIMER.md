## 1. 기본 개념

### 1.1 신경망의 부품
- **층(layer):** 입력을 받아 계산하고 출력을 내는 한 단계. 모델은 층을 수십~수백 개 쌓은 것이다.
- **conv(합성곱 층):** 이미지 모델의 기본 층. 작은 필터를 이미지 위에서 움직이며 곱하고 더한다. "1×1 conv"는 필터 크기가 1칸이라, 같은 위치의 채널들을 섞기만 한다. "3×3 conv"는 주변 3×3칸을 본다.
- **채널(channel):** 한 층의 출력은 "높이 × 너비 × 채널 수" 모양의 숫자 덩어리다. 채널 하나는 한 종류의 특징(예: 세로선, 털 질감)을 담은 지도라고 보면 된다. 512채널이면 그런 지도가 512장이다.
- **weight(가중치):** 층이 학습으로 얻은 숫자. conv의 필터 값이 weight다. 모델 파일의 크기는 거의 weight가 차지한다.
- **activation(활성값):** 이미지를 넣었을 때 층과 층 사이를 흐르는 중간 계산값. 이미지마다 달라진다.
- **FP(full precision):** 양자화하지 않은 원래 모델. 숫자를 32-bit 소수로 쓴다. 이 문서에서 "FP 모델"은 정답 기준이 되는 원본이다.

### 1.2 양자화란
숫자를 적은 비트의 정수로 바꿔 저장하고 계산하는 것이다. 모델이 작아지고, 정수 연산이라 전력과 시간이 줄어든다. 스마트폰이나 로봇 같은 **엣지 기기**에 모델을 넣으려면 거의 필수다.

```
양자화:   q  = clamp( round(x / Δ) + z ,  0,  2^b − 1 )      # 실수 x → 정수 q
역양자화: x̂ = (q − z) · Δ                                    # 정수 q → 근사 실수 x̂
```

- **b(비트 수):** 4-bit면 정수 16개(0~15), 8-bit면 256개로만 표현한다.
- **Δ(scale, 눈금 간격):** 실수 범위를 2^b칸으로 나눈 한 칸의 크기. 범위가 넓으면 한 칸이 커진다.
- **z(zero point):** 실수 0에 해당하는 정수.
- **clamp:** 범위를 벗어난 값을 끝값으로 잘라 붙이는 것.
- **양자화 오차:** x − x̂. 한 칸 안의 값은 모두 같은 정수가 되므로 그만큼 정보가 사라진다.

**비유.** 키를 1mm 단위로 재다가 10cm 단위 자로 바꾸는 것과 같다. 눈금이 성길수록(비트가 적을수록) 사람들 사이의 차이가 뭉개진다. 그리고 2m 넘는 사람 한 명 때문에 자의 범위를 0~3m로 잡으면, 같은 칸 수로 더 넓은 범위를 덮어야 해서 눈금이 더 성겨진다. 이 "극단값(outlier) 때문에 눈금이 성겨지는 문제"가 이 연구의 핵심 원인이다.

### 1.3 눈금을 어떤 단위로 정하나
| 방식 | 뜻 | 이 연구에서 |
|---|---|---|
| **per-channel** | 채널마다 눈금(Δ, z)을 따로 둔다 | weight에 사용 (출력 채널마다) |
| **per-tensor** | 텐서 전체가 눈금 하나를 쓴다 | activation에 사용 |

activation을 채널마다 따로 양자화하면 정확하지만, 대부분의 기기가 지원하지 않는다. 그래서 표준 설정인 per-tensor를 쓴다. 이 때문에 "채널마다 크기가 다르면 작은 채널이 뭉개진다"는 문제가 생긴다(§5.3의 M이 다루는 문제).

### 1.4 "W4A8" 표기
- **W**는 weight 비트, **A**는 activation 비트다. W4A8은 weight 4-bit, activation 8-bit다.
- 숫자가 작을수록 모델은 작아지지만 오차가 커진다. 이 연구의 설정은 W8A8(쉬움), W4A8, W4A6, W4A5(어려움)다.

### 1.5 PTQ와 QAT
- **QAT(quantization-aware training):** 양자화된 상태로 모델을 다시 학습시킨다. 정확하지만 학습 데이터 전체와 긴 학습 시간이 필요하다.
- **PTQ(post-training quantization):** 학습이 끝난 모델을 재학습 없이, 이미지 몇백 장만 보고 양자화한다. 싸고 빠르다. **이 연구는 PTQ다.**
- **calibration(보정) 이미지:** PTQ가 눈금을 정하려고 보는 소량의 이미지. 여기서는 COCO 학습 이미지 256장이다. 정답 라벨은 쓰지 않는다.

### 1.6 눈금은 어떻게 정하나 (observer)
calibration 이미지를 모델에 넣어 각 층의 activation 값을 모으고, 그 분포를 보고 범위 [최소, 최대]를 정한다. 이 일을 하는 부품을 **observer**라고 한다.
- **min-max:** 관측한 최소·최대를 그대로 쓴다. 극단값에 약하다.
- **MSE:** 범위를 조금씩 줄여 보며 양자화 오차가 가장 작은 범위를 고른다. 극단값 몇 개를 잘라 내는 대신 나머지를 촘촘히 표현한다. 이 연구의 기본값이다.

### 1.7 fake quantization(양자화 흉내)
실험에서는 실제 정수 연산을 하지 않는다. "양자화했다가 곧바로 되돌리는" 계산으로 정밀도 손실만 재현한다. 결과는 같고 구현이 쉽다. 그래서 이 연구의 숫자는 **정확도**에 대한 것이고, 실제 기기에서의 **속도**는 따로 재야 한다.

### 1.8 기준이 되는 기존 PTQ 방법들
| 이름 | 한 줄 설명 |
|---|---|
| **naive (RTN)** | 가장 가까운 정수로 반올림만 한다. 아무 보정도 없다 |
| **AdaRound** | weight마다 "올림할지 내림할지"를 학습한다. 가장 가까운 쪽이 항상 최선은 아니기 때문이다 |
| **BRECQ** | AdaRound를 층 하나가 아니라 블록(층 묶음) 단위로 한다. 블록 출력이 FP와 같아지도록 맞춘다. 가장 널리 쓰이는 강한 기준선이다 |
| **QDrop** | BRECQ에 "일부 activation은 양자화하지 않고 흘리는" 무작위성을 더해 일반화를 노린다 |
| **LSQ** | activation의 눈금 간격(Δ)도 학습하는 기법. BRECQ·QDrop 안에서 같이 쓴다 |

우리 방법은 이들을 대체하지 않는다. **BRECQ(또는 QDrop)가 돌기 전에 모델을 손보는 단계**를 추가한다.

## 2. 대상 모델(YOLO-World)의 구조와 각 블록의 역할

### 2.1 무엇을 하는 모델인가
- **객체 검출(object detection):** 이미지에서 물체의 위치(박스)와 종류(클래스)를 찾는다.
- **보통의 검출기:** 학습 때 정한 클래스(예: COCO 80개)만 찾을 수 있다.
- **open-vocabulary 검출기(OVOD):** 찾을 클래스를 **글자(텍스트 프롬프트)로** 준다. "소화기", "휠체어"처럼 학습 때 없던 이름도 넣을 수 있다. 엣지에서는 배포 뒤에 찾을 대상이 바뀌는 일이 흔해서 이런 모델이 유용하다.
- **어떻게 가능한가:** 이미지의 각 영역을 벡터(**region 임베딩**)로 만들고, 클래스 이름도 텍스트 인코더(CLIP)로 벡터(**텍스트 임베딩**)로 만든다. 두 벡터가 비슷하면(내적이 크면) 그 클래스라고 판정한다. 이 비교를 **contrastive** 방식이라고 한다.

### 2.2 전체 흐름

```
 이미지 640×640
   │
   ▼ backbone (블록 0~9): 이미지에서 특징을 뽑는다
   │   0 Conv → 1 Conv → 2 C2f → 3 Conv → 4 C2f → 5 Conv → 6 C2f → 7 Conv → 8 C2f → 9 SPPF
   ▼ neck (블록 10~22): 크기가 다른 특징들을 섞고, 텍스트 정보를 넣는다
   │   10 Upsample → 11 Concat → 12 C2fAttn → 13 Upsample → 14 Concat → 15 C2fAttn
   │   16 ImagePoolingAttn → 17 Conv → 18 Concat → 19 C2fAttn → 20 Conv → 21 Concat → 22 C2fAttn
   ▼ head (블록 23): 박스와 클래스 점수를 낸다
       cv2: 박스 위치    cv3: region 임베딩    cv4: 임베딩 × 텍스트 = 클래스 점수
```

문서에서 `12.cv2`처럼 쓰는 이름은 "12번 블록 안의 cv2라는 conv"라는 뜻이다.

### 2.3 블록별 역할
| 블록 | 하는 일 | 이 연구에서의 의미 |
|---|---|---|
| **Conv** (0, 1, 3, 5, 7, …) | conv + 정규화 + 활성 함수. 대부분 해상도를 절반으로 줄이며 채널을 늘린다 | `1.conv`(두 번째 conv)는 양자화에 민감한 곳 중 하나다. 이미지에 가까운 초반 층은 값의 분포가 넓다 |
| **C2f** (2, 4, 6, 8) | 입력을 둘로 나누고(split), 한쪽을 작은 conv 묶음(bottleneck)에 여러 번 통과시킨 뒤, 중간 결과를 모두 이어 붙여(concat) 1×1 conv로 합친다. 적은 계산으로 다양한 깊이의 특징을 섞는 YOLOv8의 기본 블록이다 | 안의 `cv1`은 입구 conv, `cv2`는 이어 붙인 것을 합치는 출구 conv다. **출구 conv는 성질이 다른 분기들을 한꺼번에 받는다.** 그래서 눈금 공유 문제가 생기기 쉽다 |
| **SPPF** (9) | 여러 크기로 최댓값 풀링을 해서 넓은 범위의 문맥을 모은다 | 특별한 문제는 없었다 |
| **Upsample / Concat** (10, 11, 13, 14, …) | 해상도를 키우고, 다른 단계의 특징과 이어 붙인다. 큰 물체용 특징과 작은 물체용 특징을 섞기 위해서다 | weight가 없어 양자화 대상이 아니다 |
| **C2fAttn** (12, 15, 19, 22) | **C2f에 텍스트 attention 분기를 하나 더 붙인 블록.** 이미지 특징과 텍스트 임베딩의 유사도로 "게이트"를 만들어 특징에 곱한다. 텍스트와 관련 있는 위치를 강조하는 역할이다 | **문제의 중심.** §4에서 자세히 본다 |
| **ImagePoolingAttn** (16) | 반대 방향의 융합. 이미지 특징을 요약해 텍스트 임베딩을 조금 고친다 | v1 모델에만 있다. 이 뒤의 블록(19, 22)은 고쳐진 텍스트를 받는다 |
| **head cv2** | 박스 위치를 예측한다. 결과는 DFL이라는 고정 연산으로 좌표가 된다 | 마지막 1×1은 8-bit로 둔다 |
| **head cv3** | 각 위치의 region 임베딩(512차원 벡터)을 낸다 | 이 벡터가 틀어지면 클래스 판정이 바뀐다. 마지막 conv 입력은 16-bit로 둔다(§6.2) |
| **head cv4** | region 임베딩과 텍스트 임베딩의 내적으로 클래스 점수를 낸다 | conv가 아니라 행렬곱이다. 확정 프로토콜에서 8-bit로 양자화한다 |

**P3 / P4 / P5**는 head가 받는 세 가지 해상도의 특징 지도다. P3는 가장 촘촘해서 작은 물체를, P5는 가장 성겨서 큰 물체를 맡는다.

### 2.4 C2fAttn을 자세히
12번 블록 기준으로, 각 분기는 128채널이다.

```
 x ─ cv1 (1×1) ─ split ─┬─ y0 ───────────────────────────────────────┐
                        └─ y1 ─┬──────────────────────────────────────┤
                               ▼                                      │
                          bottleneck (3×3 conv 두 개) ─ y2 ─┬──────────┤
                                                           ▼          │
                              attention(y2, 텍스트) ─ y3 = p ⊙ aw ─────┤
                                                                      ▼
                        cv2 (1×1)  ◀──  concat(y0, y1, y2, y3)   512채널
```

attention 분기 안에서는 이렇게 계산한다.

```
p   = proj_conv(y2)                                           # 이미지 특징을 한 번 더 변환
aw  = sigmoid( max_j ⟨embed(y2), guide_j⟩ / √d + bias )        # 게이트: 위치마다 0~1
y3  = p ⊙ aw                                                  # 위치별로 곱한다
```

- `guide_j`는 j번째 클래스 이름의 텍스트 임베딩이다.
- `⟨a, b⟩`는 내적(두 벡터가 얼마나 비슷한지)이다.
- `max_j`는 "어떤 클래스와든 가장 잘 맞는 정도"를 고른다.
- `sigmoid`는 값을 0~1로 누르는 함수다.
- 결과적으로 `aw`는 "이 위치에 프롬프트로 준 물체 중 무언가가 있을 법한가"를 나타내는 지도다. 이것을 **게이트**라고 부른다.

## 3. 성능을 재는 법

### 3.1 AP
- **AP(average precision):** 검출 성능의 표준 지표. 박스 위치와 클래스를 모두 맞혀야 하고, 0~100 사이 값이다. 높을수록 좋다.
- **COCO AP:** COCO 데이터(80개 클래스)에서 잰 AP.
- **LVIS AP:** LVIS 데이터(1203개 클래스)에서 잰 AP. 클래스가 많고 서로 비슷한 것이 많아 훨씬 어렵다.
- **APr:** LVIS에서 드물게 나오는(rare) 클래스만의 AP.

### 3.2 calibration 어휘와 held-out 어휘
- PTQ는 calibration 때 COCO 80개 클래스를 프롬프트로 넣는다. 이것이 **calibration 어휘**다.
- 평가할 때 LVIS 1203개 클래스는 calibration 때 본 적이 없다. 이것이 **held-out 어휘**다.
- open-vocabulary 모델의 가치는 "본 적 없는 어휘에서도 잘 되는가"에 있다. 그래서 **held-out 어휘에서의 성능이 이 연구의 주 관심사**다.

### 3.3 flip과 lost (판정 충실도)
AP는 정답 라벨과 비교한다. 이 연구는 여기에 **"양자화한 모델이 원래 모델과 같은 판정을 내리는가"**를 직접 재는 지표를 더했다.

- **LVIS_flip:** FP 모델이 확신하는 위치(점수 sigmoid > 0.25)에서, 1등 클래스가 양자화 후 다른 클래스로 바뀐 비율(%). **낮을수록 좋다.**
- **LVIS_lost:** FP 모델은 맞혔는데 양자화 후 틀리게 된 개수.

**왜 필요한가.** W4A8 BRECQ는 COCO AP가 3.6점만 떨어진다. 그런데 LVIS 판정의 18%가 다른 클래스로 바뀐다. AP 하나만 보면 이 손상이 가려진다. 이것이 논문의 출발점이다.

### 3.4 seed, 짝 비교, 신뢰구간
- **seed:** 무작위성의 출발 번호. PTQ에는 무작위 요소(표본 추출 등)가 있어서 seed마다 결과가 조금 다르다. 한 번의 결과만 보면 우연일 수 있으므로 seed 0~5로 6번 돌린다.
- **평균 ± 표준편차:** 6번의 평균과 흩어진 정도.
- **짝 비교(paired difference):** 같은 seed에서 "우리 방법 − BRECQ"를 구해 그 차이들의 평균을 본다. 두 방법이 같은 무작위성을 공유하므로 차이를 더 정확히 볼 수 있다.
- **95% 신뢰구간(CI):** "+1.15 ± 0.16"은 참값이 0.99~1.31 사이에 있을 것으로 본다는 뜻이다. 구간이 0을 포함하지 않으면 차이가 우연이 아니라고 본다.
- **p값과 Holm 보정:** p값은 "실제로는 차이가 없는데 우연히 이만큼 나올 확률"이다. 여러 비교를 한꺼번에 하면 우연히 유의해 보이는 것이 생기므로, Holm 방법으로 p값을 엄격하게 고친다.
- **붕괴 seed:** 어떤 seed에서 기준선이 유독 크게 무너지는 경우가 있다(W4A5 seed 0). 평균에 그대로 넣으면 우리 방법의 이득이 부풀려진다. 그래서 그 seed를 밝히고, 뺀 값도 함께 보고한다.

## 4. 문제를 찾아간 과정

이 절이 논문의 **분석(Analysis)** 부분에 해당한다. 각 단계를 "왜 → 어떻게 → 결과 → 그래서"로 적는다.

### 4.1 출발: 손실 함수로는 안 됐다
- **왜.** 처음에는 "held-out 판정을 지키도록 학습하는 손실 함수"를 만들려고 했다(PromptCal, vocabulary metric).
- **결과.** W4A8에서 모든 변형이 BRECQ보다 나빴다(LVIS AP −0.1 ~ −0.65점). COCO는 오르는데 LVIS는 떨어졌다.
- **그래서.** 질문을 바꿨다. "어떻게 학습할까"가 아니라 **"손상이 모델의 어디에서 생기는가"**를 먼저 알아야 했다.

### 4.2 진단 1 — 블록 단위로 어디가 아픈지 찾기 (runs/128)
- **왜.** 손상이 모델 전체에 고르게 퍼져 있다면 구조적인 해법이 없다. 특정 위치에 몰려 있다면 그곳만 고치면 된다. 어느 쪽인지부터 알아야 했다.
- **어떻게.** 학습 없이 두 가지 실험을 했다.
  - **drop(내려 보기):** 전부 8-bit인 모델에서 **블록 하나만** weight를 4-bit로 내린다. 그때 LVIS flip이 얼마나 느는지 본다. "이 블록 하나가 얼마나 망가뜨리는가"를 잰다.
  - **restore(되돌려 보기):** 전부 4-bit인 모델에서 **블록 하나만** 8-bit로 되돌린다. flip이 얼마나 줄어드는지 본다. "이 블록만 고치면 얼마나 회복되는가"를 잰다.
  - 두 방향을 다 보는 이유: 하나만 보면 다른 블록과의 상호작용 때문에 착시가 생길 수 있다.
- **결과.**
  - drop: **12번 블록 하나**가 flip을 +67.8%p 늘렸다. 다른 블록은 훨씬 작았다.
  - 12번 블록 안을 conv 단위로 쪼개니, **`12.cv2` 하나**가 +66.5%p였다.
  - restore: `12.cv2` 하나를 되돌리면 전체 회복분 28.6%p 중 27.0%p가 돌아왔다.
- **그래서.** 손상은 몰려 있다. 범인은 12번 블록(C2fAttn)의 출구 conv다.

### 4.3 진단 2 — 그 conv 안에서 무슨 일이 벌어지나 (`12.cv2` 분해)
- **왜.** "여기가 아프다"만으로는 고칠 수 없다. 왜 아픈지 알아야 처방이 나온다. `12.cv2`는 네 분기를 이어 붙인 것을 받으므로, 분기별로 나눠 봤다.
- **어떻게.** FP 모델에 이미지를 넣고, `12.cv2`의 입력과 weight를 분기별로 통계 냈다. 그리고 이 conv만 따로 떼어 여러 방식으로 양자화하면서 출력 오차(FP 출력과의 상대 차이)를 쟀다.
- **결과 1 (통계).**

  | 분기 | activation 평균 크기 | activation 최대 | 받는 weight의 최대 |
  |---|---|---|---|
  | y0, y1 (cv1 조각) | 0.44 / 0.34 | 7.7 / 7.0 | 0.81 / 0.64 |
  | y2 (bottleneck) | 0.45 | 9.3 | 0.89 |
  | **y3 (텍스트 attention)** | **1.62** | **20.4** | **3.32** |

  텍스트 attention 분기만 값이 3~4배 크다. 일부 채널은 입력값과 weight가 **동시에** 크다(모델 전체에서 1·2위, 같은 conv 안 중앙값의 87배).
- **결과 2 (오차).**

  | 양자화 방식 | 출력 상대 오차 |
  |---|---|
  | W8A8 | 0.005 |
  | W4A8 | **0.83** (출력이 사실상 파괴) |
  | 분기마다 weight 눈금을 따로 | 0.24 |
  | 크기 상위 2채널만 8-bit | 0.073 |

- **해석.** weight는 출력 채널마다 눈금 하나를 쓴다. 그 눈금의 범위가 attention 분기의 큰 weight(3.32)에 맞춰진다. 4-bit는 16칸뿐이라 한 칸이 너무 커지고, 나머지 분기의 작은 weight(0.2 안팎)는 대부분 0이 된다. 여기에 attention 분기의 큰 activation이 반올림 오차를 증폭한다. **"큰 값을 가진 분기 하나가 공유 눈금을 망가뜨린다"**가 원인이다.

### 4.4 진단 3 — 다른 설명을 하나씩 배제하기 (runs/139)
- **왜.** 그럴듯한 설명이 하나 나왔다고 끝내면 안 된다. 다른 가설로도 설명되는지 확인해야 논문에서 "원인은 이것"이라고 쓸 수 있다.
- **어떻게.** 가설 다섯 개를 세우고, 가설마다 그것만 바꾸는 실험을 했다. 모두 학습 없이 한다.

  | 가설 | 내용 | 실험 | 판정 |
  |---|---|---|---|
  | H1 | LVIS는 비슷한 클래스가 많아서 작은 오차에도 뒤집힌다 | 점수 차가 큰 판정과 작은 판정을 나눠 flip을 센다 | **보조 요인.** 다만 점수 차가 큰 확실한 판정도 70% 넘게 뒤집혀서 이것만으로 설명되지 않는다 |
  | H2 | 오차의 방향이 텍스트 임베딩 쪽으로 치우쳐 있다 | 오차와 텍스트 공간의 정렬 정도(rho)를 잰다 | **기각.** 오히려 기준보다 낮았다 |
  | H3 | 텍스트 attention 분기가 원인이다 | `12.cv2`를 W4로 두되 attention 분기의 weight 열만 8-bit로 둔다 | **지지.** flip 79.2% → **6.9%** (기준 6.5%와 같은 수준) |
  | H4 | 손상이 특정 해상도에 몰린다 | P3/P4/P5별로 flip을 센다 | 부분 지지. `12.cv2`는 P4·P5, `15.cv2`는 P3에 영향 |
  | H5 | 프롬프트로 준 어휘가 영향을 준다 | 프롬프트를 COCO로 바꿔 본다 | **기각.** 80.3% vs 79.2% |

- **결과.** attention 분기의 weight 열은 모델 전체 weight의 **0.26%**다. 이것만 8-bit로 두면 손상이 거의 다 사라진다.
- **그래서.** 원인이 확정됐다. 그리고 "그 분기를 다른 분기와 떼어 놓으면 된다"는 처방의 방향이 나왔다(→ G).

### 4.5 진단 4 — 나머지 손상은 어디에 (runs/134)
- **왜.** `12.cv2`만 고쳐도 BRECQ 뒤에는 손상이 남았다. 텍스트 융합 conv 네 개를 모두 8-bit로 둬도 LVIS AP는 +0.65점뿐이었다.
- **어떻게.** conv 하나씩 4-bit로 내리는 진단을 모든 conv에 대해 했다. 이번에는 **평가 데이터를 보지 않는 방식**으로 다시 했다(학습 이미지 200장, COCO 어휘만). 4.2의 진단은 평가 이미지와 LVIS를 써서, "어디를 보호할지 고르는" 용도로 쓰면 누수가 되기 때문이다.
- **결과.** 상위는 `12.cv2`, `1.conv`, `2.cv2`, `4.cv1`이었다. `12.cv2` 다음은 모두 **초반 backbone**이다. 이 넷을 보호하면 +1.25점이 된다.
- **해석.** 초반 층은 이미지에 가까워 값의 분포가 넓고, C2f의 나누기·이어 붙이기 경계에서 성질이 다른 분기가 눈금을 공유한다. 텍스트와는 무관한 두 번째 손상 지점이다.
- **그래서.** 손상은 **두 곳**에 몰려 있다. ① 텍스트 융합 conv, ② 초반 backbone 경계.

### 4.6 진단 5 — 다른 모델에서도 그런가 (runs/137, 154, 164)
- **왜.** 모델 하나에서만 그렇다면 일반적인 발견이 아니다.
- **어떻게.** 같은 누수 없는 진단을 다른 모델에 돌렸다.
- **결과.**

  | 모델 | 진단이 고른 보호 대상 |
  |---|---|
  | YOLO-World-S | 12.cv2, 1, 2.cv2, 4.cv1 |
  | YOLO-World-S v2 | 12.cv2, 15.cv2, 1 |
  | YOLO-World-M | 12.cv2, 15.cv2 |
  | YOLOE-v8s (텍스트 융합 없음) | 1, 2.cv2, 4.cv2, 15.cv2, 4.cv1, … (초반 backbone 위주) |

- **그래서.** 텍스트 융합이 있는 모델은 융합 conv가 1순위다. 융합이 없는 YOLOE에서는 초반 backbone만 남는다. 분석의 두 축이 모델을 넘어 재현된다.

### 4.7 진단 6 — "이전은 취약성을 옮긴다" (runs/148)
- **왜.** scale 이전(M, §5.3)을 단독으로 쓰면 W8A8에서는 좋아지는데 저비트에서는 오히려 나빠졌다. 이유를 알아야 했다.
- **어떻게.** 이전을 적용하기 전과 후에, conv별 민감도 진단을 각각 돌려 비교했다.
- **결과.** `12.cv2`의 민감도는 줄었다. 대신 `1.conv`의 민감도가 3.5~4배로 늘었다.
- **해석.** 이전은 activation의 부담을 weight로 옮긴다. 부담이 사라지는 것이 아니라 자리를 옮긴다. 옮겨 간 곳이 약하면 거기서 터진다.
- **그래서.** 이전은 보호(P)나 게이트 교환(G)이 약한 곳을 받쳐 줄 때만 이득이 된다. 확정 프로토콜의 ablation에서도 확인된다(W4A5: M 단독 −0.75점, G 위에서는 +0.59점).

## 5. 우리 방법: G, P, M

세 단계는 각각 §4에서 찾은 문제 하나를 겨냥한다.

| 단계 | 겨냥하는 문제 | 한 줄 요약 | 추가 비용 |
|---|---|---|---|
| **G** 게이트 교환 | 텍스트 분기가 공유 눈금을 망가뜨림 (§4.3, 4.4) | 텍스트 분기를 전용 conv로 떼어 낸다 | 0 |
| **P** 보호 | 초반 backbone의 민감한 conv (§4.5) | 민감한 conv 몇 개만 8-bit로 둔다 | 크기 +0.3% |
| **M** 이전 | activation의 채널별 크기 편차 | 편차를 weight 쪽으로 옮긴다 | 0 |

### 5.1 G: 게이트 교환 (이 연구가 새로 제안하는 부분)

**수식.** 1×1 conv는 선형 연산이다. 선형이란 `f(a + b) = f(a) + f(b)`이고 `f(c·a) = c·f(a)`라는 뜻이다. 여기서 두 가지가 나온다.
1. 이어 붙인 입력에 대한 conv는, 분기별 conv 결과의 합과 같다.
2. 게이트 `aw`는 위치마다 숫자 하나를 곱하는 것이고 1×1 conv는 위치를 섞지 않으므로, 곱하기를 conv 뒤로 옮겨도 결과가 같다.

```
원래:    cv2( concat(y0, y1, y2,  p ⊙ aw) )

바꾼 뒤:  W_main · concat(y0, y1, y2) + b    +    Σ_h  aw_h ⊙ ( W_h · p_h )
```

- `W_main`은 원래 cv2 weight에서 앞 세 분기에 해당하는 열, `W_h`는 텍스트 분기의 h번째 head에 해당하는 열이다. 원래 weight를 잘라 쓰는 것이라 새로 학습하지 않는다.
- **head**는 attention을 여러 묶음으로 나눠 계산하는 단위다. 게이트가 head마다 하나씩 있어서 head별로 나눈다.
- 양자화하지 않으면 결과가 원래와 정확히 같다. 이를 **FP 등가**라고 한다.

**왜 좋아지나.**
1. 텍스트 분기가 전용 conv를 가져서 다른 분기와 눈금을 공유하지 않는다. §4.3의 원인이 구조적으로 사라진다.
2. 양자화되는 입력이 게이트를 곱하기 전의 `p`다. 게이트가 만드는 위치별 크기 차이가 양자화 범위에서 빠진다.
3. 게이트가 작은 위치에서는 텍스트 분기의 양자화 오차도 게이트만큼 줄어든다.

**코드** (`quant/fusion_quant.py`, 읽기 쉽게 줄임)

```python
def gate_commute(block):                      # block = C2fAttn 하나
    conv = block.cv2.conv                     # 원래의 1×1 conv
    n_main = conv.in_channels - block.c       # 앞 세 분기의 채널 수
    # weight를 입력 채널(열) 기준으로 자른다
    block.cv2_main = _split_conv(conv, slice(0, n_main), bias=True)
    block.cv2_side = nn.ModuleList(           # head마다 텍스트 분기 전용 conv
        _split_conv(conv, slice(n_main + h*hc, n_main + (h+1)*hc), bias=False)
        for h in range(nh))
    del block.cv2                             # 원래 conv는 더 쓰지 않는다

    def forward(self, x, guide):              # guide = 텍스트 임베딩
        y = list(self.cv1(x).split((self.c, self.c), 1))      # y0, y1
        y.extend(m(y[-1]) for m in self.m)                     # y2 (bottleneck)
        aw = attn_gate(self.attn, y[-1], guide)                # 게이트 [배치, head, 높이, 너비]
        p  = self.attn.proj_conv(y[-1])                        # 게이트를 곱하기 전
        out = self.cv2_main(torch.cat(y, 1))                   # 앞 세 분기
        for h, side in enumerate(self.cv2_side):
            out = out + aw[:, h:h+1] * side(p[:, h*hc:(h+1)*hc])   # conv 먼저, 게이트는 뒤에
        return self.act(out)
```

**어떻게 확인했나.**
- **등가성:** 바꾸기 전후의 출력을 비교했다. 차이는 부동소수점 오차 수준이다.
- **효과 (학습 없이, 12번 블록만 4-bit):** LVIS flip이 68.8% → **9.7%**로 줄었다. 눈금만 분기별로 나누면 18.5%였다. 즉 "게이트를 뒤로 옮긴 것" 자체가 효과의 절반 이상이다.
- **BRECQ와 함께 (W4A5, 6 seed):** G 하나로 LVIS AP +1.37점, flip −5.4%p다. 세 요소 중 단독 효과가 가장 크다.

### 5.2 P: 보호

**아이디어.** 모든 층을 같은 비트로 내리지 않고, 민감한 층만 높은 비트로 둔다. 이를 **혼합 정밀도(mixed precision)**라고 한다. 방식 자체는 기존에 있는 것이다. 이 연구에서 신경 쓴 것은 **어디를 보호할지를 누수 없이 고르는 것**이다.

**진단 절차** (`rank_convs_leakfree`)
1. 학습 이미지 200장을 FP 모델에 넣어, 각 위치의 1등 클래스(COCO 어휘)를 저장한다.
2. 전부 8-bit인 모델에서 conv **하나만** weight를 4-bit로 내린다.
3. 1등 클래스가 바뀐 비율(flip)이 얼마나 늘었는지 기록한다.
4. 모든 conv에 대해 반복한다.

**누수(leak)란.** 평가에 쓰는 데이터(평가 이미지, LVIS 클래스 이름)를 방법을 정하는 데 쓰는 것이다. 그러면 평가 성능이 실제보다 좋게 나온다. 시험 문제를 미리 보고 공부하는 것과 같다. 그래서 진단에는 학습 이미지와 COCO 어휘만 쓰고, LVIS는 불러오지도 않는다.

**선택 코드** (`diag_w4_sensitivity.py`)

```python
def select_protected(rows, budget_frac=0.015, criterion="coco"):
    total  = sum(r["mparam"] for r in rows)       # 전체 weight 파라미터 수
    budget = budget_frac * total                   # 예산: 1.5%
    sel, used = [], 0.0
    for r in sorted(rows, key=lambda r: r[criterion], reverse=True):   # flip 증가가 큰 순서로
        if used + r["mparam"] <= budget * 1.1:     # 예산의 110%를 넘지 않게 담는다
            sel.append(r["name"]); used += r["mparam"]
        if used >= budget * 0.9:                   # 90% 이상 차면 멈춘다
            break
    return sel
```

**G와 함께 쓸 때.** G가 C2fAttn의 cv2를 대신 처리하므로 그 conv는 보호 목록에서 뺀다. YOLO-World-S에서는 `1, 2.cv2, 4.cv1`만 남고, 추가 크기는 +0.3%다.

**어떻게 확인했나 (W4A8, 6 seed, 같은 예산).**

| 보호 방식 | LVIS AP 변화 | LVIS flip 변화 |
|---|---|---|
| 무작위로 고른 conv | +0.21 | −0.5%p |
| HAWQ식(출력 오차 기준) | +0.90 | −5.5%p |
| 우리 진단(판정 flip 기준) | +1.05 | −5.7%p |

- 무작위와의 차이가 크다. **효과는 "8-bit를 더 썼다"가 아니라 "어디에 썼는가"에서 나온다.**
- HAWQ식과는 비슷하다. 그래서 논문에서 "선택 기준이 새롭다"고 주장하지 않는다. 주장하는 것은 손상 위치의 분석이다.

### 5.3 M: 공유 제약 scale 이전

**문제.** activation은 텐서 전체가 눈금 하나를 쓴다(§1.3). 채널 A의 값이 0~1이고 채널 B가 0~20이면 눈금이 B에 맞춰져서 A가 뭉개진다.

**수식.** 입력 채널 c를 양수 `s_c`로 나누고, 그 채널을 받는 weight 열에 `s_c`를 곱하면 결과가 같다.

```
y = conv(x, W) = conv( x / s ,  W · s )
```

- 큰 채널은 크게 나눠서 다른 채널과 크기를 맞춘다. activation 눈금이 덜 낭비된다.
- 대신 그 채널의 weight가 커진다. weight는 출력 채널마다 눈금이 따로 있어 이 편차를 더 잘 견딘다.
- `s_c = (그 채널 activation의 최대값)^α / (그 채널 weight의 최대값)^(1−α)`. α는 얼마나 옮길지 정하는 값이다.
- 이 아이디어는 SmoothQuant, AWQ라는 기존 기법과 같은 계열이다.

**"공유 제약"이란.** 실제 기기에서 "x를 s로 나누는" 일은 그 값을 **만든 쪽 conv**가 한다. 그래서 두 규칙을 지켜야 실제로 배포할 수 있다.
1. 같은 출력을 여러 conv가 받으면, 그 conv들은 같은 s를 써야 한다.
2. 덧셈(residual add)으로 합쳐지는 채널들도 같은 s여야 한다.

코드는 "어느 입력 채널이 어느 출력 채널에서 왔는지"를 자동으로 추적한다. 방법은 앞 conv의 출력을 채널마다 조금씩 다르게 흔들어 보고, 뒤 conv의 입력이 어떻게 변하는지 보는 것이다. 그렇게 같은 s를 써야 하는 채널들을 묶음으로 만든다.

**탐색 코드** (`quant/channel_graph.py`, 핵심만)

```python
for unit in units:                                # 같은 s를 써야 하는 묶음 단위로
    best_err, best_s = 오차(s=1), None             # "옮기지 않음"도 후보
    for a in (0, 0.25, 0.5, 0.75, 1):             # α 후보
        s = xmax ** a / wmax ** (1 - a)
        err = sum(                                # 영향받는 모든 conv에서 오차를 잰다
            norm( conv(Q(x / s), Q(W * s)) - conv(x, W) )**2 / norm( conv(x, W) )**2
            for conv in affected)
        if err < best_err: best_err, best_s = err, s
    if best_s is not None:
        apply_migration(best_s)                    # W에 s를 곱해 두고, 입력은 s로 나눈다
```

`Q(·)`는 양자화다. "옮기지 않음"이 후보에 있으므로 각 conv의 오차는 나빠지지 않는다. 그런데도 모델 전체로는 나빠질 수 있다(§4.7).

**M을 켤지 미리 검사한다.** YOLO-World-M에서는 M이 P나 G 위에서도 해로웠다. 평가 결과를 보고 모델별로 빼면 누수가 된다. 그래서 누수 없는 검사로 정한다.

```python
# calibration에 쓰지 않은 학습 이미지 200장, COCO 어휘
flip_off, flip_on = mcheck_flip([M을_끈_모델, M을_켠_모델], ...)
use_M = flip_on <= 1.5 * flip_off        # 켰을 때 판정이 1.5배 넘게 나빠지면 끈다
```

- calibration 이미지를 쓰지 않는 이유: BRECQ가 그 이미지에 맞춰 이미 조정했기 때문에, 문제가 가려질 수 있다.
- 결과: YOLO-World-S, v2, YOLOE는 켬. YOLO-World-M은 끔(켜면 flip이 2~7배).
- 한계: v2 W8A8에서는 M이 LVIS 판정만 나쁘게 하는데, 이 검사로는 잡히지 않는다.

### 5.4 세 단계가 합쳐지는 순서

```python
gate_commute_all(model)                  # G: 구조만 바꾼다 (결과는 원래와 같다)
wrap_convs(model, w_bits=4, a_bits=5)    # 모든 conv를 "양자화 흉내" 모듈로 감싼다
set_first_last_bits(model, 8)            # 첫·마지막 층은 8-bit
set_last_abits(model, 16)                # head 마지막 conv의 입력만 16-bit
set_conv_wbits(model, 보호목록, 8)        # P: 보호 대상의 weight만 8-bit
quantize_attention(model, "attn_cls")    # attention·contrastive 연산도 8-bit
search_and_apply_tied(model, ...)        # M: 채널 scale 이전 (검사를 통과한 모델만)
calibrate(model, 이미지_256장)            # 눈금(Δ, z)을 정한다
optimize_brecq(model, fp_model, ...)     # BRECQ: 올림/내림을 조정한다
```

순서가 중요하다. G, P, M은 모두 눈금을 정하기(calibrate) **전에** 해야 한다. 눈금이 바뀐 구조와 값에 맞춰 정해져야 하기 때문이다.

## 6. 실험 조건에서 헷갈리기 쉬운 것들

### 6.1 프로토콜이란
"무엇을 몇 비트로 양자화하고, 어떻게 평가하는가"의 약속이다. 프로토콜이 다르면 숫자를 비교할 수 없다. 모든 방법(기준선과 우리 방법)에 같은 프로토콜을 적용한다.

**확정 프로토콜(10-02)**

| 항목 | 설정 | 이유 |
|---|---|---|
| 양자화 대상 | 모든 conv (head 포함) | 일부만 양자화하면 실제 배포와 다르다 |
| 첫·마지막 층 | 8-bit | 입력 이미지를 받는 층과 최종 출력을 내는 층은 민감해서 8-bit로 두는 것이 이 분야의 관례다 |
| head 마지막 conv의 입력 | 16-bit | §6.2 |
| attention, contrastive 행렬곱 | 8-bit | §6.3 |
| FP로 남는 것 | LayerNorm, softmax, sigmoid, 덧셈, DFL, NMS | 원소별 연산과 후처리라 보통 양자화하지 않는다 |

### 6.2 왜 head 마지막 conv 입력만 16-bit인가
- **무슨 일이 있었나.** YOLO-World-M에서 같은 방법을 seed만 바꿔 돌렸는데 COCO AP가 40.4와 24.3으로 갈렸다.
- **어떻게 찾았나.** 두 seed의 차이는 activation 범위뿐이다. 범위를 conv 절반씩 다른 seed의 값으로 바꿔 보며 범인을 좁혔다(이분 탐색). head cv3의 마지막 conv 하나가 원인이었다.
- **왜 그런가.** MSE observer가 표본을 무작위로 뽑는데, 이 conv의 입력은 값의 범위가 넓어서 뽑힌 표본에 따라 범위가 0~115와 0~144로 달라졌다.
- **해결.** 그 입력만 16-bit로 두면 범위에 덜 민감해져 두 seed 모두 40.7이 됐다.
- **왜 모든 모델에 적용하나.** M 모델에만 적용하면 "평가 결과를 보고 모델별로 설정을 바꾼" 것이 된다. 그래서 프로토콜로 정해 모든 모델에 똑같이 적용한다.

### 6.3 왜 attention과 contrastive도 8-bit로 양자화하나
- 처음에는 conv만 양자화했다. 그런데 LVIS처럼 클래스가 1203개면, head의 contrastive 행렬곱이 전체 행렬 연산의 약 24%다. 이것이 FP로 남으면 "엣지용으로 양자화했다"는 주장이 약해진다.
- 8-bit로 양자화해도 결론이 그대로인지 6 seed로 확인했고, 그대로였다. 그래서 프로토콜에 넣었다.
- 덕분에 모델의 실제 크기도 줄었다(W4 기준 약 7.9 MiB → 6.6 MiB).

### 6.4 PM, GPM, GP 같은 이름
조건 이름은 `기반+접미사`다. `brecq+GPM`은 BRECQ 위에 G, P, M을 모두 쓴 것이다.

| 이름 | 뜻 |
|---|---|
| `brecq` | 기준선 |
| `brecq+G`, `+P`, `+M` | 요소 하나만 |
| `brecq+PM`, `+GP`, `+GM` | 두 요소 |
| **`brecq+GPM`** | **우리 방법** |
| `brecq+R`, `+H` | 비교용: 무작위 보호, HAWQ식 보호 |
| `qdrop+GPM` | 기반을 QDrop으로 바꾼 것 |

### 6.5 왜 "방법은 GPM 하나"로 고정했나
W4A8에서는 PM이 GPM보다 0.34점 높다. 그렇다고 비트마다 더 좋은 쪽을 골라 "우리 방법"이라고 하면, 평가 결과를 보고 고른 것이 된다. 그래서 방법은 GPM으로 고정하고, PM은 "크기를 1% 더 쓰는 변형"으로 같은 표에 싣는다.

### 6.6 모델마다 실제 구성이 다른 이유
방법은 같지만, 모델의 구조와 검사 결과에 따라 실제로 켜지는 요소가 다르다.

| 모델 | 실제로 동작하는 것 | 이유 |
|---|---|---|
| YOLO-World-S, v2 | G + P + M | 전부 해당 |
| YOLO-World-M | G | M은 검사에서 꺼진다. P의 대상이 전부 G가 처리하는 conv라 남는 것이 없다 |
| YOLOE-v8s | P + M | 텍스트 게이트가 없어 G가 할 일이 없다 |

### 6.7 리더보드의 "프로토콜" 필터
`LEADERBOARD.html`에는 예전 프로토콜의 결과도 들어 있다. 논문에 쓰는 것은 **"확정 (attn8+A16)"**뿐이다.

## 8. 논문을 처음 쓸 때 헷갈리는 용어와 관행

| 용어 | 뜻 | 이 연구에서 |
|---|---|---|
| **baseline(기준선)** | 비교 대상이 되는 기존 방법 | naive, AdaRound, BRECQ, QDrop, PromptCal |
| **ablation** | 방법의 요소를 하나씩 빼거나 넣어 각 요소의 기여를 보는 실험 | W4A5에서 G, P, M의 모든 조합(표 2) |
| **control(대조군)** | "효과가 정말 그 원인 때문인가"를 확인하려고 넣는 비교 | 무작위 보호 R. "8-bit를 더 써서 좋아진 것 아니냐"를 배제한다 |
| **plug-in** | 다른 방법 위에 그대로 얹을 수 있음 | QDrop 위에서도 같은 효과(표 3b) |
| **generalization(일반화)** | 다른 모델·설정에서도 통하는가 | v2, M, YOLOE(표 4, 5) |
| **novelty(새로움)** | 기존 연구에 없던 기여 | 손상 위치와 원인의 분석, 게이트 교환(G) |
| **contribution(기여)** | 논문이 내세우는 것의 목록 | 문제 정의, 분석, G, 배포 가능한 파이프라인 |
| **limitation(한계)** | 방법이 통하지 않거나 확인하지 못한 범위 | §7의 한계. 숨기지 않고 쓰는 것이 신뢰를 높인다 |
| **negative result(음성 결과)** | "이건 안 됐다"는 결과 | calibration 어휘로 학습하는 PromptCal은 held-out을 해친다 |
| **Pareto** | 두 기준(예: 크기와 성능)을 함께 볼 때, 어느 쪽도 손해 없이 더 좋은 대안이 없는 점들의 경계 | promptcal-ptq의 `figures/pareto_size_vs_accuracy.png` |
| **leak(누수)** | 평가 데이터가 방법 설계에 새어 들어가는 것 | 진단과 M 검사에서 평가 이미지와 LVIS를 쓰지 않는다 |
| **cherry-picking** | 유리한 결과만 골라 보고하는 것 | 비트마다 좋은 구성을 고르지 않고 GPM으로 고정한 이유 |
| **reproducibility(재현성)** | 같은 조건에서 같은 결과가 나오는가 | 조건마다 무작위 상태를 복원해, 따로 돌려도 묶어 돌려도 결과가 같다 |

**논문에서 자주 받는 질문과 이 연구의 답**
1. **"기존 기법을 섞은 것 아닌가?"** P와 M은 기존 계열이고 그렇게 쓴다. 새로운 것은 원인 분석과 G다. 각 요소는 분석에서 찾은 문제 하나씩을 겨냥한다.
2. **"flip은 직접 만든 지표인데 믿을 수 있나?"** AP와 함께 보고한다. flip은 AP보다 먼저 움직이고 seed 간 흔들림이 작다. 드문 클래스의 AP(APr)도 함께 오른다.
3. **"왜 AP가 조금밖에 안 오르나?"** 양자화의 손상 자체가 몇 점 수준이다. 그 손상의 26~91%를 되찾는다.
4. **"실제로 빨라지나?"** 속도는 양자화 일반의 이득이다. 우리 방법은 BRECQ와 같은 연산 구조라 추가 비용이 없다는 것이 주장이고, 실제 측정은 남은 일이다.
