## 0. 제목과 이름 (교수님 확인 필요)

**제목 (권장):** *Where Low-Bit Quantization Breaks Open-Vocabulary Detectors: Diagnosis-Guided Post-Training Quantization*
- "Where ... breaks"가 Motivation(분석), "Diagnosis-Guided PTQ"가 Method에 1:1로 맞는다.
- 다른 후보: *Diagnose, Then Quantize: ...* ("Preserving"이 W4A4 결과에 비해 강함), *AP Is Not Enough: ...* (분석 논문처럼 읽힘), *TriageQ: ...* (분석 기여가 제목에서 사라짐).

**방법 이름 (권장):** **TriageQ**. 진단해서 처치를 고른다는 은유가 "진단이 G·P·M 중 무엇을 쓸지 정한다"와 맞는다. 대안은 PinpointQ.
- 정하기 전에 arXiv와 Google Scholar에서 이름 충돌을 확인한다.

**기법 이름:** **G** = Gate Commutation, **P** = Diagnosis-guided Protection, **M** = Constrained Scale Migration.

## 0.1 기존 개요와 달라지는 점

기존 개요는 진단 중심이었다(3 지표·진단 → 4 분석 → 5 처방). 교수님 틀은 Motivation → Method 구조라서 다음 두 가지를 정한다.

1. **진단(D)과 분석을 Motivation(3절)에 넣는다.** "기존 PTQ의 한계를 Figure로 보인다"는 요구에 기존 4절(손상 집중 + 구조 따라감 + 게이트 메커니즘)이 그대로 맞는다. 진단 절차도 3절에서 정의해 두면, 4.2 P와 4.3 M에서 "3.2의 진단을 쓴다"고만 쓰면 된다.

## Abstract

한 단락, 150–250단어(6–8문장). 순서는 **배경 → 문제 → 원인 → 기법 → 결과**다.

**먼저 바로잡을 표현**
1. **PTQ는 "사전학습이 필요 없는" 방식이 아니다.** 사전학습된 모델을 **재학습(fine-tuning) 없이** 소량의 calibration 이미지로 양자화하는 방식이다. "학습 데이터 전체와 재학습 없이"라고 쓴다.
2. **flip은 원인이 아니라 증상을 재는 지표다.** 원인 분석은 "손상이 구조가 정하는 소수 지점에 몰려 있다"이고, flip은 그 손상을 드러내고 측정하는 도구다. flip은 **문제** 단계에, 집중된 손상은 **원인** 단계에 둔다.

**① 배경 (1–2문장)**
- OVOD는 배포 뒤에 사용자가 어휘를 바꿀 수 있어 엣지 기기 수요가 많다.
- 엣지에서 돌리려면 저비트 양자화가 필요하고, 재학습 없이 적용할 수 있는 PTQ가 현실적인 선택이다.
- **"배포 후 어휘가 바뀐다"**는 말을 꼭 넣는다. ② 문제로 이어지는 연결고리다.

**② 문제 (1–2문장)**
- 기존 PTQ는 calibration 어휘(COCO)의 AP로 조정하고 평가한다.
- 이 방식은 주된 실패를 가린다. AP는 버티는 것처럼 보여도 **처음 보는 어휘의 판정이 먼저 무너진다.**
- 수치 예: W4A8 BRECQ에서 YOLO-World-S의 COCO AP 하락은 3점 이내지만, LVIS에서 FP가 확신한 예측의 약 17%가 다른 클래스로 바뀐다(flip).
- "OVOD 양자화 연구가 적다"는 반 문장 정도로만 쓴다.
- "그대로 적용하면 성능이 크게 낮아진다"만 쓰면 흔한 주장이 된다. **"AP로는 보이지 않는다"**가 이 논문만의 문제 제기다.

**③ 원인 (1–2문장)**
- calibration 쪽 데이터만 쓰는 누수 없는 층별 진단을 해 보면, 손상은 고르게 퍼져 있지 않다. **weight 1.5%가 손상의 48–72%를 담는다**(CNN 검출기 5개).
- 위치는 구조를 따른다. 텍스트 게이트 검출기는 텍스트 융합 conv, 게이트 없는 검출기는 초반 backbone, ViT는 여러 층에 분산된다.
- 텍스트 융합 conv의 메커니즘(게이트 분기가 공유 scale을 오염)은 지면이 있으면 반 문장으로 넣는다.

**④ 기법 (2문장)**
- 진단 결과가 세 가지 학습 없는 처방 중 무엇을 쓸지 정한다.
  - **G:** 비트 비용 없이 FP와 동일한 게이트 교환
  - **P:** 진단된 층만 8bit로 보호 (weight 메모리 +1.6%)
  - **M:** 배포 제약을 지키는 scale 이전. 누수 없는 검사가 승인할 때만 켠다.
- BRECQ와 QDrop 위에 얹는 plug-in이다.
- 방법 이름이 정해지면 여기서 "We propose X"로 처음 등장시킨다.

**⑤ 결과 (1–2문장)**
- 8개 검출기(YOLO-World S/S-v2/M/L, YOLOE ×2, OWLv2, Grounding DINO)에서 held-out LVIS AP가 오르고 flip이 줄어든다.
- 기존 PTQ가 무너지는 W4A4에서도 동작한다.
- 수치 후보 ([RESULTS_FINAL.md](RESULTS_FINAL.md) 기준):

| 용도 | 수치 | 비고 |
|---|---|---|
| 안정적인 대표값 | S W4A8: AP +1.49, flip 17.7% → 10.7% | 3 seed |
| 최대 이득 | L W4A5: +13.65 ± 0.91 | 3 seed. 이전에는 BRECQ seed 0 붕괴 때문에 빼기로 했으니 교수님과 확인 |
| W4A4 | S 18.60 vs BRECQ 0.43 | Ours는 seed 0만 있음 |

## 2. Related Works

네 단락으로 쓰고, 각 단락 끝에 "우리와의 차이"를 한 문장씩 둔다.
- **PTQ:** AdaRound, BRECQ, QDrop. 검출 PTQ(Reg-PTQ)는 인용만 한다.
- **Outlier와 scale 이전:** SmoothQuant, AWQ. CLE는 SiLU에서 FP 등가가 성립하지 않는다고 한 줄 쓴다.
- **혼합 정밀도:** HAWQ, HAQ. 차이는 외부 제약 아래에서 비트를 배분하는 게 아니라, 손상이 몰려 있어서 작은 고정 예산이면 된다는 점이다.
- **OVOD:** YOLO-World, YOLOE, OWLv2, GLIP, Grounding DINO. OVOD 양자화 연구는 거의 없다는 점을 쓴다.

## 4. Method

**4절 도입 단락 + 전체 그림 (Fig. 4).** input → OVOD(Text Encoder / Backbone / RepVL-PAN / Head) → output 파이프라인 위에 기법을 배지처럼 붙이는 형태다. 지금 [figures/method_arch.png](../figures/method_arch.png)가 이 형태이고, 고칠 곳은 [placement 문서](FIGURE_METHOD_PLACEMENT_2026-11-04.md) §8에 있다. 핵심은 다음과 같다.
- G는 T-CSPLayer 4곳에만 붙인다.
- P는 백본 앞쪽 1·2·4·6에만 붙인다.
- M은 conv → conv 연결 전체에 걸리고, T-CSPLayer 출력은 제외한다.
- D(진단)는 모델 밖 점선 영역에 둔다.
- 빌드 순서는 배지 번호(①–⑤)로 보인다.

| 절 | 들어갈 내용 |
|---|---|
| 4.1 G | 식 `cv2(concat(y0,y1,y2,p⊙a)) = W_main·[...] + Σ a_h⊙(W_h·p_h)`. FP 등가이고 비트 비용은 0이다. 적용 조건은 구조(텍스트 게이트)라서 데이터를 보지 않는다. 원래 구조와 G 적용 후를 나란히 그린 펼친 그림을 넣는다 |
| 4.2 P | 3.2 진단의 상위 층을 고정 예산 1.5% 안에서 W8로 둔다. G 대상은 먼저 빼고 예산을 다시 채운다. 근거는 집중도이고, "1.5%를 집중도를 보고 정했다"고는 쓰지 않는다. 크기는 +1.6% |
| 4.3 M | 생산 conv가 공유하는 s와 residual 제약을 설명한다. 채널 계보는 측정으로 찾고, xmax는 calibration 전체에서 잰다. **사전 검사**(calibration 밖 flip, ρ=1.0)로 M을 켤지 정한다 |
| (4.4 또는 4.3 끝) | BRECQ/QDrop 위 plug-in이라는 점과 빌드 순서를 한 단락으로 쓴다 |

**5.5 Discussion에 넣을 관찰**
- **Findings:** 집중도가 P의 효과를 예측한다(OWLv2는 집중도 35%라 P 효과가 없음). M은 취약성을 옮긴다(12.cv2 → 1.conv). P 예산은 M과 함께일 때만 성능으로 이어진다.
- **비용:** 크기 +1.4–1.6%, 진단 시간(S 약 10분).
- **한계:** W4A4는 FP 대비 −7. M 검사가 놓치는 경우가 있다(S W4A8, v2 W8A8). 실기기 지연은 측정하지 않았다.
