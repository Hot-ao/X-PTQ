# GDINO 추가 과정에서 바뀐 점 (2026-10-30 ~ 10-31)

GDINO(Grounding DINO-T)를 붙이면서 생긴 변경은 두 가지다.

1. **기법 정의 변경**: M의 xmax에 하한을 추가했다. 모든 모델에 해당한다.
2. **GDINO 구조에 맞춘 연결 작업**: 기법 변경이 아니다. 베이스라인에도 똑같이 적용했다.

논문 서술에 영향을 주는 것은 1번이다.

---

## 1. M: 채널 최댓값(xmax)에 하한 추가

### 바뀐 점

| | 기존 | 변경 후 |
|---|---|---|
| 스케일 | s = xmax^α / wmax^(1−α), 기하평균으로 정규화 | 같음 |
| xmax 측정 | α 탐색용 이미지 8장(MIG_IMAGES)의 채널별 최댓값 | 같은 8장. 단 `xmax = max(xmax, 0.003 · 단위 최댓값)` |
| α 후보 / 선택 | {0, .25, .5, .75, 1, 끔}, W·A 양자화 출력 오차로 선택 | 같음 |
| 하한 적용 범위 | – | YOLO 계열: 소비 conv 단위 (`quant/channel_graph.py`) |
| | | OWL·GDINO: 단위 기준 (`core/owl_quant.py`, `core/gdino_quant.py`) |

- 옵션: `--xmax-floor`(하한), `--mig-stat {8,all}`(xmax 측정 이미지 수).
- 기본값: 11-01부터 모든 진입점(`run_gdino.py`, `run_comparison.py`, `run_owl.py`)이 8장 + 0.003이다. 하한 0은 10-31 이전 규칙이다.

### 바꾼 이유
- GDINO의 ReLU 뒤 단위(encoder/decoder FFN fc2, text enhancer fc2, box MLP)는 채널 활성화가 희소하다.
  - 8장에서 0이었다가 다른 이미지에서 켜지는 채널이 있었다.
  - 그 크기는 8장 기준의 최대 4.5×10⁵배였다(held-out 200장 기준).
- 이런 채널은 s가 약 1e-5로 잡힌다. 그래서 x/s가 폭주하고, brecq+M W4A5의 COCO AP가 **0.01**로 떨어졌다.
- 기존 안전장치는 "s = 1 후보를 넣어 M 때문에 나빠지지 않게 한다"는 것이었다. 하지만 이 장치는 8장 안에서만 작동한다.
  - 8장에서 0인 채널은 오차를 만들지 않으므로 위험이 보이지 않는다.
  - 따라서 GDINO만의 문제가 아니라 **정의 자체의 구멍**이다.
- xmax를 8장으로 잰 것은 버퍼를 공유하려는 구현 편의였을 뿐, 의도한 설계는 아니었다.

### 하한 값 선택 (`runs/217_mig_rule/floor_scan.log`)

| 하한 | 기존 모델 α 변화 | GDINO held-out 최대 초과배율 |
|---|---|---|
| 0 (기존) | – | 4.46e5 |
| 0.1% | 전 모델 0 | 740 |
| **0.3% (채택)** | **전 모델 0**. S·YOLOE ×2는 s까지 완전히 동일 | 291 |
| 1% | S 1단위, OWL 1단위, GDINO 2단위 | 129 |

- 선택 기준: 기존 모델의 α 결정을 하나도 바꾸지 않는 가장 큰 값.
- 이 기준은 학습 쪽 데이터만 쓴다.

### 검토했지만 채택하지 않은 안: xmax를 calib 256장으로 측정
- 원리상 더 깔끔하다.
- YOLO-World-S에서의 차이는 작았다(LVIS 기준).

  | 비트 | 8장 | 256장 |
  |---|---|---|
  | W4A8 | 23.47 | 23.94 |
  | W4A5 | 22.37 | 22.37 |

- 하지만 기존 모델 α의 20~50%가 바뀐다.
  - A8 기준 S 20/51, m 16/65, L 20/79, YOLOE 16/51·16/61, OWL 4/41.
  - 이 경우 전체 재실험에 약 170~180 GPU-h(GPU 3장으로 약 2.5일)가 든다.
- 그래서 부록 ablation 후보로만 남긴다.
- GDINO 256장 모델은 `/data/taeho/cvpr2027_qmodels/gdino/mig256/`에 보관했다.

### 결과로 달라진 점

**GDINO W4A5**

| 조건 | COCO AP | 비고 |
|---|---|---|
| naive | 42.33 | val 500장 |
| naive+M, 하한 없음 | 붕괴 | val 500장 |
| naive+M, 8장 + 0.3% | 43.81 | val 500장. mcheck 21.97 → 16.75 |
| brecq | 40.33 | val 5000장 |
| brecq+PM (256장 + 1% 규칙) | 41.78 | val 5000장 |
| QDrop | 41.79 | val 5000장 |

- 8장 + 0.3%로 만든 brecq+M / brecq+PM은 재실행 중이다(`runs/218_gdino_m8`).

**기존 모델**
- S·YOLOE ×2: s까지 완전히 동일하다. 결과는 그대로다.
- m·L·OWL: α와 on/off는 동일하다. 8장에서 거의 0이던 채널의 s만 다르다.
  - L W4A8 재실행 결과: 변화가 seed 편차 안에 있다(아래 3절).
- 자원: clamp 한 번이라 시간·메모리 변화가 없다.

### 이점
- 구조와 상관없이 하나의 정의로 쓸 수 있다. ReLU 희소 활성화(DETR 계열)에서도 안전하므로 일반화 주장이 강해진다.
- S·YOLOE·v2와 m 주 결과(M 끔)는 하한을 넣어도 같은 모델이 만들어진다. 하한이 실제로 작동하는 m W4A4·L·OWL은 11-01에 하한을 넣어 다시 돌린다([PROGRESS.md](PROGRESS.md)).
- 하한이 없을 때의 붕괴를 ablation으로 보이면 설계의 근거가 된다.

### 우려점과 대응

| 우려 | 대응 |
|---|---|
| 하이퍼파라미터가 하나 늘어남 | 부록에 민감도 표 추가: 0.1%·0.3%·1% 모두 붕괴를 막음 |
| 0.3% 선택에 COCO val 500장 AP가 참고로 섞임 | 논문에는 학습 쪽 기준(α 불변 + calib 밖 train 이미지 mcheck)만 기술. val AP를 빼도 결론이 같음 |
| m·L·OWL은 비트 단위로 동일하지 않음 | seed 0 검증에서는 차이가 편차 안이었다. 그래도 11-01에 하한을 넣어 전부 다시 돌려 표를 교체한다(옛 코드 결과라는 기재가 필요 없게) |
| 사후 수정으로 보일 수 있음 | 하한이 있는 정의로 기술하고, 하한 없을 때의 붕괴는 ablation으로 제시 |
| GDINO 하한 0.3%에서도 held-out 초과배율이 최대 291× | 붕괴는 막음. 남은 차이는 A 양자화 클리핑이 흡수함 |
| GDINO 판단과 평가가 모두 COCO 어휘, 단일 seed | LVIS 1000장 평가 완료(4절). 두 번째 1000장 평가 예정, seed 추가는 미정 |

## 2. GDINO 구조에 맞춘 연결 작업 (기법 변경 아님)

| 항목 | 내용 | 이유 | 우려 |
|---|---|---|---|
| 재구성 단위 (`quant/brecq_units.py`) | 경로 목록 기반 BRECQ/QDrop. kwargs 캡처, tuple 출력 중 주 출력만 사용, token 단위 loss, batch 1 | HF 층은 mask·pos 등을 kwargs로 받고 tuple을 반환함 | 알고리즘은 같지만 코드 경로가 YOLO와 다름 |
| decoder는 FP 입력으로 재구성 | query 선택 이후 단위는 FP 모델 입력을 사용 | two-stage query 선택이 달라지면 입력과 목표가 어긋남 | BRECQ 원 절차와 약간 다름 |
| 양자화 프로토콜 (`core/gdino_quant.py`) | attention 8bit, softmax 16bit, box head 출력 W8A16, 패치 conv W8A8 | YOLO의 첫/끝 8bit 관례를 대응시킴. softmax 8bit는 −1.2 손상 | 모델별 프로토콜 차이 |
| 단위 구성 | recon 41개, M 62개. post-norm LN 뒤와 fusion 층은 M에서 제외 | "1/s를 앞단에 접을 수 있는 곳만"이라는 기존 규칙 | M 적용 범위가 좁음 |
| G | 미적용 | 곱셈형 텍스트 게이트가 없음 | 적용 조건을 논문에 명시해야 함 |
| 판정 지표 | box 매칭 기반 flip/lost (IoU 0.5) | anchor가 없음 | YOLO의 flip과 수치를 직접 비교할 수 없음 |
| 평가 | COCO 5000장 + LVIS minival 일부(1000장 단위) | LVIS는 1203 어휘를 chunk 32개로 나눠야 해서 전체 4809장이면 모델당 약 20시간 | 다른 모델(전체 minival)과 같은 표에 두려면 subset임을 표기 |

### S·YOLOE ×2 나머지 비트 설정 (완료, `runs/221_floor_bits`)
- W8A8·W4A6·W4A4 전부에서 α가 바뀐 단위 0, s 변화 0이었다.
- W4A8·W4A5는 앞의 floor scan에서 이미 같은 결과였다.
- calibration 8장은 seed와 무관하다.
- 따라서 이 세 모델은 모든 비트 설정, 모든 seed에서 하한을 넣은 M과 기존 M이 같은 모델을 만든다.

## 4. GDINO LVIS 평가 (minival 앞 1000장, W4A5, seed 0, `runs/220_gdino_lvis`)

| 조건 | LVIS AP | APr | APc | APf | LVIS flip | lost | (COCO AP) |
|---|---|---|---|---|---|---|---|
| FP32 | 34.43 | 42.62 | 32.02 | 35.05 | – | – | 48.50 |
| BRECQ | 31.72 | 31.53 | 31.10 | 31.98 | 24.01 | 1.97 | 40.33 |
| QDrop | 33.76 | 35.48 | 33.01 | 33.98 | 27.58 | 1.81 | 41.79 |
| +M | 34.57 | 38.37 | 33.97 | 34.64 | 25.96 | 1.84 | 41.12 |
| **+PM** | **34.96** | 45.17 | 33.58 | 35.09 | 25.04 | 1.98 | 41.19 |

- 평가 전에 정한 기준: PM이 QDrop보다 LVIS AP에서 1점 이상 높으면 1000장으로도 충분하다고 본다.
- 결과: PM은 QDrop보다 +1.20, BRECQ보다 +3.24 높다. 기준을 넘는다.
- COCO에서는 PM이 QDrop보다 0.6 낮았는데, 보지 않은 어휘(LVIS)에서는 순서가 뒤집혔다.
- 주의: PM, M, QDrop의 APc와 PM, M의 LVIS AP가 FP보다 높게 나왔다.
  - 1000장 subset의 노이즈이거나, LVIS의 비완전 라벨(federated) 특성 때문으로 보인다.
  - 따라서 절대값보다 같은 이미지 위의 차이로 해석해야 한다.
  - APr은 rare 클래스 수가 적어서 참고만 한다.
